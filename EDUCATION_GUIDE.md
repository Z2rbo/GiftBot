# Руководство по терминологии и архитектуре программирования

## 📚 Основные термины и концепции

### 1. API (Application Programming Interface)
**Что это:** Интерфейс для взаимодействия между приложениями или компонентами системы.

**Простыми словами:** API — это "меню ресторана" для программистов. Вы видите список доступных "блюд" (функций), но не знаете, как они готовятся на кухне (внутренняя реализация).

**Примеры:**
- **REST API** — веб-сервисы, работающие через HTTP (GET, POST, PUT, DELETE)
- **GraphQL API** — более гибкий способ запроса данных
- **Telegram Bot API** — для создания ботов в Telegram
- **TON Connect API** — для интеграции с блокчейном TON

**Зачем нужно:** Позволяет использовать функционал других сервисов без знания их внутреннего устройства.

---

### 2. Cloudinary
**Что это:** Облачный сервис для управления медиа-файлами (изображения, видео).

**Основные возможности:**
- Загрузка и хранение файлов
- Автоматическая оптимизация изображений
- Преобразование форматов
- Ресайз, обрезка, фильтры
- CDN (быстрая доставка по всему миру)

**Пример использования:**
```javascript
// Загрузить изображение
cloudinary.uploader.upload("photo.jpg", {
  folder: "avatars",
  transformation: [{ width: 200, height: 200, crop: "fill" }]
})
```

**Зачем нужно:** Не нужно хранить и обрабатывать медиа на своем сервере — всё делает Cloudinary.

---

### 3. Sniffer (не "snoofer")
**Что это:** Инструмент для перехвата и анализа сетевого трафика.

**Типы:**
- **Packet Sniffer** — перехватывает пакеты данных в сети
- **HTTP Sniffer** — анализирует HTTP-запросы
- **Browser DevTools** — встроенный "сниффер" в браузере

**Инструменты:**
- Wireshark (для сетевого трафика)
- Charles Proxy (для HTTP/HTTPS)
- Browser DevTools Network tab
- Postman (для тестирования API)

**Зачем нужно:** Отладка, анализ запросов, понимание как работает взаимодействие между клиентом и сервером.

---

### 4. Модульное программирование (Modular Programming)
**Что это:** Разделение кода на независимые, переиспользуемые модули.

**Принципы:**
- **Разделение ответственности** — каждый модуль делает одну вещь
- **Инкапсуляция** — скрытие внутренней реализации
- **Переиспользование** — модули можно использовать в разных проектах
- **Тестируемость** — легко тестировать отдельные модули

**Пример структуры:**
```
project/
  ├── modules/
  │   ├── auth.js      # Модуль авторизации
  │   ├── database.js  # Модуль работы с БД
  │   ├── api.js       # Модуль API запросов
  │   └── utils.js     # Вспомогательные функции
  └── main.js          # Главный файл, использующий модули
```

---

### 5. Архитектура проекта
**Что это:** Структура и организация кода в проекте.

**Популярные паттерны:**

#### MVC (Model-View-Controller)
- **Model** — данные и бизнес-логика
- **View** — представление (UI)
- **Controller** — связь между Model и View

#### Layered Architecture (Слоистая архитектура)
```
Presentation Layer (UI)
    ↓
Business Logic Layer
    ↓
Data Access Layer
    ↓
Database
```

#### Microservices (Микросервисы)
Разделение приложения на независимые сервисы, которые общаются через API.

---

### 6. Дополнительные важные термины

#### Backend (Бэкенд)
Серверная часть приложения, которая обрабатывает логику, работает с БД, API.

#### Frontend (Фронтенд)
Клиентская часть — то, что видит пользователь (интерфейс).

#### Database (База данных)
Хранилище структурированных данных (PostgreSQL, MongoDB, MySQL).

#### Middleware (Промежуточное ПО)
Код, который выполняется между запросом и ответом (авторизация, логирование).

#### Framework (Фреймворк)
Готовая структура для разработки (React, Express, Django).

#### Library (Библиотека)
Набор готовых функций для решения конкретных задач.

#### Dependency (Зависимость)
Внешние библиотеки/пакеты, которые использует проект.

#### Environment Variables (Переменные окружения)
Конфигурационные данные, хранящиеся отдельно от кода (API ключи, пароли).

#### Containerization (Контейнеризация)
Упаковка приложения в контейнер (Docker) для единообразного запуска.

#### CI/CD (Continuous Integration/Deployment)
Автоматизация тестирования и развертывания кода.

## 🎯 План обучения модульному программированию и архитектуре

### Этап 1: Основы (1-2 недели)
**Цель:** Понять базовые концепции

1. **Изучите основы JavaScript/TypeScript**
   - Функции, объекты, массивы
   - ES6 модули (import/export)
   - Асинхронность (async/await, Promises)

2. **Практика:**
   - Создайте простой проект с разделением на файлы
   - Используйте import/export для связи модулей

**Задание:** Создайте калькулятор, разделенный на модули:
- `operations.js` — математические операции
- `calculator.js` — основная логика
- `ui.js` — интерфейс

---

### Этап 2: Модульная структура (2-3 недели)
**Цель:** Научиться правильно организовывать код

1. **Изучите принципы SOLID:**
   - **S**ingle Responsibility — одна ответственность
   - **O**pen/Closed — открыт для расширения, закрыт для изменения
   - **L**iskov Substitution — подстановка
   - **I**nterface Segregation — разделение интерфейсов
   - **D**ependency Inversion — инверсия зависимостей

2. **Практика:**
   - Рефакторинг существующего кода
   - Разделение на модули по функциональности

**Задание:** Реорганизуйте ваш Telegram бот:
```
bot/
  ├── modules/
  │   ├── handlers/      # Обработчики команд
  │   ├── services/      # Бизнес-логика
  │   ├── database/      # Работа с БД
  │   ├── api/          # Внешние API
  │   └── utils/        # Утилиты
  ├── config/           # Конфигурация
  └── index.js          # Точка входа
```

---

### Этап 3: Паттерны проектирования (3-4 недели)
**Цель:** Изучить популярные паттерны

1. **Основные паттерны:**
   - **Singleton** — один экземпляр класса
   - **Factory** — создание объектов
   - **Observer** — подписка на события
   - **Repository** — абстракция доступа к данным
   - **Service** — бизнес-логика

2. **Практика:**
   - Реализуйте паттерны в реальных проектах
   - Анализируйте код популярных библиотек

**Задание:** Создайте систему уведомлений используя паттерн Observer.

---

### Этап 4: Архитектурные паттерны (4-5 недель)
**Цель:** Понять как строить большие приложения

1. **Изучите:**
   - **MVC/MVP/MVVM** — разделение ответственности
   - **Clean Architecture** — чистая архитектура
   - **Hexagonal Architecture** — порты и адаптеры
   - **Event-Driven Architecture** — событийно-ориентированная

2. **Практика:**
   - Постройте проект используя выбранную архитектуру
   - Сравните разные подходы

**Задание:** Переделайте проект используя Clean Architecture:
```
src/
  ├── domain/          # Бизнес-логика (независима от фреймворков)
  ├── application/     # Use cases (сценарии использования)
  ├── infrastructure/  # Реализация (БД, API, файлы)
  └── presentation/    # UI/API endpoints
```

---

### Этап 5: Работа с API и внешними сервисами (2-3 недели)
**Цель:** Интеграция с внешними системами

1. **Изучите:**
   - REST API (HTTP методы, статусы, заголовки)
   - GraphQL (запросы, мутации)
   - WebSockets (real-time коммуникация)
   - OAuth/JWT (авторизация)

2. **Практика:**
   - Создайте клиент для внешнего API
   - Постройте собственный API endpoint
   - Используйте Postman для тестирования

**Задание:** Интегрируйте Cloudinary в ваш проект для загрузки изображений.

---

### Этап 6: Управление зависимостями (2 недели)
**Цель:** Правильная работа с пакетами и зависимостями

1. **Изучите:**
   - npm/yarn/pnpm — менеджеры пакетов
   - package.json — конфигурация проекта
   - Версионирование (semantic versioning)
   - Lock файлы (package-lock.json)

2. **Практика:**
   - Создайте собственный npm пакет
   - Используйте приватные репозитории

---

### Этап 7: Тестирование (3-4 недели)
**Цель:** Написание надежного кода

1. **Изучите:**
   - Unit тесты (тестирование модулей)
   - Integration тесты (тестирование взаимодействия)
   - E2E тесты (end-to-end)
   - Test-Driven Development (TDD)

2. **Инструменты:**
   - Jest, Mocha (для JavaScript)
   - Mocking (заглушки для зависимостей)

**Задание:** Покройте тестами критичные модули вашего проекта.

---

### Этап 8: Документация и код-ревью (1-2 недели)
**Цель:** Поддержка и масштабирование проекта

1. **Изучите:**
   - JSDoc/TSDoc — документация кода
   - README.md — описание проекта
   - Code style guides (ESLint, Prettier)
   - Git workflow (branches, commits, PR)

2. **Практика:**
   - Напишите документацию для вашего проекта
   - Проведите код-ревью собственного кода

---

### Этап 9: DevOps и развертывание (3-4 недели)
**Цель:** Автоматизация и деплой

1. **Изучите:**
   - Docker — контейнеризация
   - CI/CD — автоматизация (GitHub Actions, GitLab CI)
   - Environment variables
   - Мониторинг и логирование

2. **Практика:**
   - Задеплойте проект на сервер
   - Настройте автоматический деплой

---

### Этап 10: Реальные проекты (постоянно)
**Цель:** Применение знаний на практике

1. **Создайте:**
   - Полноценное веб-приложение
   - API сервис
   - Микросервисную архитектуру

2. **Изучайте:**
   - Открытый исходный код популярных проектов
   - Архитектурные решения в реальных компаниях
